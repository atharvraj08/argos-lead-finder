# Argos Lead Finder: Event and Tour Announcement Sources (U.S. K-pop and J-pop)

**Verification date: 2026-10-17**

How sources were checked: live HTTP probes of every endpoint and feed (status code, newest item date), `robots.txt` for every page-based source (rules for `User-agent: *`), and the ToS, developer terms or copyright page wherever it could be fetched. Where a terms page could not be retrieved (bot-blocked, 404, or a JS-only page), the source is marked **unclear**.

**Legend for "Terms allow automated access":**
- **yes**: the terms explicitly permit this kind of programmatic or feed use.
- **yes\***: no terms page or prohibiting clause could be found, `robots.txt` permits the path, and the site publishes the feed or API itself. This is a reasonable basis to use the source, not an explicit grant.
- **no**: the terms or `robots.txt` forbid this use.
- **unclear**: the terms could not be verified. Excluded from v1.

**Ground rule for all news feeds:** consume only the feed fields (title, link, date, summary) and never crawl the article pages. Where a feed's terms require it, attribute the source and link back to the original article.

## (b) Recommended v1 sets

Shared API key: `SEATGEEK_CLIENT_ID`. GDELT needs no key.

**Change after user review (2026-10-17):** Ticketmaster Discovery was removed from v1. It lists only Ticketmaster-family events (TM, Universe, FrontGate, TicketWeb, TM Resale), so it would yield only Ticketmaster as the lead, and Ticketmaster already uses Persona (a competitor). **User decision (2026-10-17):** all RSS and GDELT sources read the full article page (`fetch_article: true`), because feed excerpts and headlines rarely contain show dates. robots.txt is still respected, and the tool falls back to feed fields when an article is blocked. Ticketmaster's subsidiaries (Universe, TicketWeb, Front Gate Tickets) are excluded along with Ticketmaster.

**Polling note (Phase 1b):** several feeds are shallow: Pollstar holds about 1 day of posts and ANN about 3 days. A weekly crawl would miss most of their items. Fix: run a small **daily** GitHub Actions job that fetches every RSS and REST source and appends new items to a cached store (for example a JSON file committed to the repo or an Actions cache). The weekly job then reads that store. Each feed is still requested only once a day.

**Coverage logic:** SeatGeek supplies event listings (including resale listings for shows sold elsewhere). News and trackers catch AXS-, DICE-, Etix- and MyMusicTaste-sold shows and announcements made before tickets are listed. The pipeline then matches news hits back to SeatGeek, or follows the "Buy Ticket" URL (from kpopofficial) to identify the seller domain.
